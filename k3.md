# K3 — VaultSquire Comprehensive Review

An independent, adversarial-but-friendly review of the whole project: every
Swift source file in `VaultSquire/`, the test suites, the Xcode project, the
governance documents, and the delivery plan.

**Review basis.** This review was performed on Linux, so it is a *static*
review: no build, no XCTest run, no interactive UI session. Everything here is
grounded in reading the code at commit `0c05294` (main at the time of review).
Runtime claims that need a Mac (rendering, focus behavior, performance
measurements) are marked **[needs macOS verification]**. The macOS Product CI
lane (`scripts/ci.sh`) remains the executing gate for every change.

**Overall verdict.** The codebase is unusually disciplined: security invariants
are enforced in one reviewed place each (clipboard, URI opening, CLI execution,
capability gating), the documentation is honest about what is *not* done, and
the test suite is broad. The gaps are almost all in the **daily-use UX layer**:
the app is a correct vault and a mediocre *launcher*. The highest-value work is
keyboard-driven copy workflows, a password generator, quick-search keyboard
navigation, and a handful of small correctness fixes in the browser view.

Finding IDs are stable; `Status` says what happened to each in this session.

## 1. Bugs and correctness

### B1 — Quick Search navigation silently drops the selection when the scope has to change
**Severity: high (feature broken in exactly the case it exists for).**

`VaultBrowserView` has two `onChange` handlers that fight each other:

1. `onChange(of: appModel.quickSearchSelection)` — sets `appModel.scope = .allVaults`
   when needed, then sets `selection = newValue`.
2. `onChange(of: appModel.scope)` — unconditionally sets `selection = nil`.

When Quick Search picks an item outside the current scope, handler 1 changes the
scope, which fires handler 2, which clears the selection handler 1 just set. The
browser jumps to All Vaults and shows… nothing. The only case that works is the
one where the scope didn't need to change.
**Status: fixed** (scope change now only clears the selection when the selected
item is genuinely not in the new scope).

### B2 — Quick Search jump mishandles `.group` scopes
**Severity: medium.**

The same handler only special-cases `.vault`. If the browser is scoped to a
*group* (a Proton share, a 1Password vault, a Vaultwarden folder) and Quick
Search picks an item from a different group — or a different vault — the
selection is set but the list doesn't contain the item, so nothing is visibly
selected and (pre-B1-fix) the selection was cleared anyway.
**Status: fixed** (the handler now asks "does the current scope contain this
item?" and switches to the owning vault's scope when it doesn't).

### B3 — A stale write error appears in a freshly opened edit sheet
**Severity: medium (user-facing, confusing).**

`AppModel.writeError` is only cleared when a write *starts*. Sequence: archive
fails → error string sits in the model → user opens the New Item sheet →
`VaultItemEditView` renders `appModel.writeError` immediately, showing
"Couldn't reach the server…" above a form the user hasn't touched.
**Status: fixed** (the model clears the error when an editor sheet is
presented).

### B4 — Archive is a single click with no confirmation and no undo
**Severity: medium (data-safety UX).**

The toolbar Archive button calls `appModel.archive(selection)` directly. There
is no confirmation dialog, no undo, and no trash view (see M11) to recover from
a mis-click. Every other destructive-ish action in the app (opening a URI) gets
a confirmation; archiving deserves one too.
**Status: fixed** (confirmation dialog naming the item).

### B5 — The "last synced" toolbar text never updates while the window is open
**Severity: low (cosmetic staleness).**

`Text(date.formatted(.relative(...)))` is evaluated once per render and nothing
re-renders the toolbar on a timer, so "2 min ago" can still say "2 min ago" an
hour later. The `.help` has the same problem.
**Status: fixed** (wrapped in a `TimelineView` that re-evaluates periodically).

### B6 — Auto-lock timeout changes require a relaunch (and have no UI at all)
**Severity: medium.**

`AutoLockController` reads its `UserDefaults` key only in `armInactivityCheck`,
which runs once at `start()`. Even setting the hidden defaults key by hand
doesn't take effect until the next launch. There is also no Settings UI for it
(see M2).
**Status: fixed** (Settings picker + `reloadPolicy()` re-arms the timer live).

### B7 — Quick Search results are a snapshot of presentation time
**Severity: low.**

`QuickSearchPanelController.show(items:…)` copies the projections once. A sync
landing while the panel is open is not reflected; an item archived while the
panel is open is still offered. Low impact (the panel is transient), but a
`results` recompute on `appModel` change would make it live.
**Status: documented, deferred.**

### B8 — `SiteIconStore` stops loading forever once 500 icons are cached
**Severity: low.**

`load(_:)` returns early when `images.count >= maximumCachedIcons`; there is no
eviction, so in a huge vault the 501st distinct site never gets an icon for the
rest of the session even after earlier ones scroll away. An LRU or
clear-oldest-half policy would do.
**Status: documented, deferred.**

### B9 — Failed unlock clears the typed master password
**Severity: low (UX friction).**

`submitUnlock` sets `passwords[account] = ""` immediately on submit, so a typo
costs a full retype. Bitwarden keeps the field populated on failure. (Clearing
is the more conservative choice and arguably deliberate; if kept, at least keep
focus in the field — untested whether it does.)
**Status: documented, deferred [needs macOS verification for focus].**

### B10 — `NSApp.activate()` may not raise the app for Quick Search on recent macOS
**Severity: unknown [needs macOS verification].**

`QuickSearchPanelController.show` calls `NSApp.activate()`, which is deprecated
in favor of `activate(ignoringOtherApps:)`. On macOS 14+ the plain variant
activates only "if appropriate"; if the panel ever appears without the app
coming forward, this is the line. Verify interactively.
**Status: documented.**

### B11 — Latent: the edit sheet's auto-close watches the *global* `isWriting`
**Severity: low (currently unreachable, fragile).**

`VaultItemEditView` closes itself on `wasWriting && !isWriting && writeError == nil`.
Today every write trigger is disabled while `isWriting` is true, so no unrelated
write can be in flight when a sheet is open — but that's an emergent property of
four separate `disabled(...)` call sites, not an invariant. A future write path
(background conflict resolution, retry) would make sheets close themselves
randomly. A per-write token would make it robust.
**Status: documented, deferred.**

### B12 — Latent: projection equality can drop list selection semantics
Not a bug today (`List` rows are tagged by `item.id`, so selection survives
content changes), but `VaultItemProjection: Hashable` includes every display
field; anything keying on the whole value instead of `id` will break across
syncs. Worth a code-comment, not code.
**Status: documented.**

## 2. Performance

### P1 — The item list is sorted twice per render
`VaultBrowserView.filteredItems` touches `appModel.items` twice (once in the
`guard`, once in the `filter`), and `AppModel.items` *sorts the whole merged
list on every access*. So every body evaluation — every keystroke in search —
sorts the vault twice.
**Status: fixed** (single local binding; one sort per evaluation).

### P2 — `AppModel.items` / `allOpenItems` recompute and re-sort on *every* access
Even after P1, each render pays O(n log n) over the merged vault. With a few
thousand items this is measurable on every keystroke and every `@Published`
tick (sync spinner!). The right fix is memoization: cache the sorted merged
array, invalidate when sessions/items change. **Status: documented, deferred**
(wants a measured before/after on hardware).

### P3 — Post-sync projection rebuild decrypts every cipher on the main actor
`AppModel.syncNow(_:)` success path calls `service.projections(...)` and
`decryptFolderNames(...)` **inside `mutate(account)`**, i.e. on the main actor.
Every cipher's name/username/URI is AES-CBC-decrypted there. On a large vault
this is a visible UI stall right after each sync — and a sync runs after every
unlock and every write. Compute the projections off-actor, then swap them in.
**Status: documented, deferred** (the change is mechanical but the
before/after belongs on hardware; also interacts with generation checks).

### P4 — `detail(for:)` re-decrypts the selected item on every browser render
The detail pane calls `appModel.detail(for: selection)` in `body`, so any
unrelated state change (sync spinner, another vault finishing opening) re-runs
the full field-by-field AES decryption of the selected item. Cache the detail
per `(itemID, generation)` and invalidate on sync/lock.
**Status: documented, deferred.**

### P5 — `VaultSlot.groups` recomputed per sidebar render
Each sidebar evaluation walks every vault's items to rebuild folder/share
counts. Fine at current scale; memoize together with P2 if vaults get large.
**Status: documented.**

### P6 — `localizedCaseInsensitiveContains` per item per field per keystroke
Both the browser filter and Quick Search use locale-aware substring matching.
It's the correct matching semantics, but it's the slowest option; if profiling
ever shows it, precompute lowercased search keys on the projection.
**Status: documented.**

### P7 — Good news
List virtualization is in place (`List` rows, icon loading keyed by host with
an in-flight set, mid-transfer byte caps on icon fetch, CLI output limits).
The expensive crypto (PBKDF2) correctly runs off the main actor because
`deriveMasterKey` is `nonisolated async`. No red flags in the launch path.

## 3. Missing features

### M1 — Global (system-wide) Quick Search hotkey
⌘⇧Space only works while VaultSquire is frontmost — it's a menu command. The
Settings UI already admits this ("A configurable global shortcut … enabled only
after their interaction and security tests pass"). This is *the* feature that
makes a password manager feel instant. Note the dependency assessment exists:
`docs/dependencies/keyboard-shortcuts.md` — adoption is gated there.
**Status: blocked on dependency gate; documented.**

### M2 — Auto-lock timeout setting
The policy engine exists; the UI didn't. **Status: implemented** (Never / 1 /
5 / 15 / 30 / 60 minutes, takes effect immediately).

### M3 — Password generator
A password manager where you can't generate a password is missing its most-used
write-side feature. **Status: implemented** (cryptographically secure via
`SystemRandomNumberGenerator`, rejection sampling, guaranteed class coverage,
length 8–64, class toggles, reveal toggle for the password field).

### M4 — Password visibility toggle in the edit sheet
The only way to check what you typed was nothing. **Status: implemented**
(eye toggle alongside the generator).

### M5 — Favorites are write-only
`VaultItemDraft.favorite` exists and the edit sheet has a Favorite toggle, but
`VaultItemProjection` carries no favorite flag: no star in the list, no
Favorites section, no filter. Users can set a favorite that does nothing.
**Status: documented, deferred** (needs projection + decryptor changes).

### M6 — No copy actions on list rows
Before this session: open item → move mouse to the tiny copy button. Now:
right-click → Copy Username / Password / One-Time Code / Open website.
**Status: implemented** (context menu; password/TOTP items disable themselves
until the item's secret fields are available).

### M7 — Keyboard copy shortcuts
⌘⇧C copy password / ⌘⇧U copy username for the selected item, Bitwarden-style.
Natural follow-up to M6 (the menu commands make it straightforward via
`Commands` + focused selection). **Status: documented, deferred.**

### M8 — Sort options
List is strictly alphabetical. "Recently used"/"Recently modified" are the two
people actually miss. Needs `revisionDate` surfaced on projections.
**Status: documented.**

### M9 — Category filter / type sections
Logins vs cards vs notes are indistinguishable in list scope. A small
category filter (or section headers) scales much better past a few hundred
items. **Status: documented.**

### M10 — Item metadata: created / modified dates, password history
The cipher model carries revision dates and password history; the detail view
shows neither. "When did I last rotate this?" is a real question with no
answer in-app. **Status: documented.**

### M11 — Trash / restore
Archive exists (now with confirmation) but there is no trashed-items view, no
restore, and no soft-delete. **Status: documented** (write-gate territory per
DELIVERY.md; tread carefully).

### M12 — Create/edit beyond logins
Only login items are creatable/editable; secure notes, cards, identities are
read-only. A deliberate slice boundary, but the top write-side gap after M3.
**Status: documented** (workstream-gated).

### M13 — Multiple Vaultwarden accounts
Hard-coded `AccountID.vaultwardenPrimary` / "primary" throughout. The code
says so itself. **Status: documented** (planned workstream).

### M14 — Argon2id unlock
Fails closed with a clear message; needs the argon2 dependency assessment in
`docs/dependencies/argon2.md`. Correctly blocked, not forgotten.
**Status: blocked on dependency gate; documented.**

### M15 — Menu-bar presence
A status-item with lock state, quick search, and lock-now. Standard for the
category. **Status: documented idea.**

### M16 — Password strength meter in the edit sheet
No dependency wanted: a local heuristic (length × class entropy estimate with
common-pattern penalties) is enough for "weak/good/strong".
**Status: documented idea.**

### M17 — Breach check (HIBP)
k-anonymity range queries are the only acceptable design given this repo's
privacy posture; even that sends *something*. Document the tradeoff before any
code. **Status: documented idea only.**

### M18 — Local audit view: reused / old / weak passwords
Everything needed is already decrypted locally at unlock. A read-only audit
pane (reused-password clusters, ancient `revisionDate`s, short passwords) is
high value and zero network. **Status: documented idea.**

### M19 — Attachments
Not present anywhere (model, decryptor, UI). A large deliberate slice.
**Status: documented.**

### M20 — SSH-key item type
Currently falls into "notes and custom fields only". **Status: documented.**

## 4. UI / UX polish

### U1 — Quick Search had no keyboard navigation
Arrow keys did nothing; Return always opened the first result; no visible
selection. A launcher without arrows is a toy. **Status: implemented** (↑/↓
move a visible selection, Return opens it, mouse still works, panel-level key
handling so the search field keeps focus).

### U2 — Quick Search rows are bare text
No item icon, no vault badge — two same-named logins from different vaults are
indistinguishable. Reuse `ItemIconView` and the capsule badge the browser
already has. **Status: documented idea** (trivial once M1-era panel work
happens).

### U3 — Unlock error presentation is static
Wrong password → red text appears. No shake, no field refocus, no haptic. A
subtle `.default` haptic + shake is the expected macOS idiom.
**Status: documented idea [needs macOS verification].**

### U4 — Revealed secrets stay revealed indefinitely
The eye toggle conceals only when toggled back or when switching items. A
nice touch: auto-conceal after ~30 s, and conceal when the window loses key
status. **Status: documented idea.**

### U5 — No badges on list rows
A tiny key/TOTP/favorite glyph cluster on the trailing edge tells you "has 2FA
seed", "is favorite" without opening the item. **Status: documented idea**
(TOTP part is projection-visible once M5's projection change lands).

### U6 — Empty-detail pane is a missed onboarding surface
"Select an item · N items in this scope" could carry the three keyboard
shortcuts the app has. Cheap, high-signal. **Status: documented idea.**

### U7 — Menu bar is sparse
Only Quick Search and Lock Vault commands. Edit/Archive/Copy actions for the
current selection belong in an app menu (needs `FocusedValue` plumbing).
**Status: documented.**

### U8 — Long vault failure messages truncate to one line in the sidebar
`rowSubtitle` is `lineLimit(1)`; a long CLI error ("…approve its prompt") is
cut with no tooltip. Add `.help(message)`.
**Status: documented, trivial.**

### U9 — Sidebar failure rows offer no retry affordance
A failed Proton/1Password open shows the message but the only retry is
re-clicking the vault row and pressing Open Vault. A small "Try Again" on the
row (or on the locked pane — which does have it) would shorten the loop.
**Status: documented idea.**

## 5. Aesthetics

The app already has a real visual identity: the locked-shell gradient rail, the
deterministic monogram tiles (FNV-1a hue per host — genuinely nice), and
continuous-corner icon shapes. These are the increments that would take it from
"tidy" to "high-value Mac app":

### A1 — Unlock transition
The swap from unlock pane to item list is instant. A 200 ms cross-fade + slight
item-list rise (`transition(.opacity.combined(with: .move))`,
`.animation(.snappy)`) makes unlocking feel like a door opening.
**Status: documented idea.**

### A2 — TOTP countdown ring
Replace the "27s" text with a small circular progress ring that drains over the
period — scannable from across the room, and the standard idiom in the
category. **Status: documented idea.**

### A3 — Detail header banner
Give the detail header a soft full-width tint derived from the item's hue
(`tint.opacity(0.08)` material band behind the large icon + title). Frames the
content and reinforces the color identity the list established.
**Status: documented idea.**

### A4 — Provider identity in the sidebar
Vault rows all share the same lock glyph. A subtle per-provider tint (not brand
assets — just a consistent hue, e.g. Vaultwarden steel blue, Proton violet,
1Password navy) on the lock icon would make a multi-provider sidebar parse
instantly. **Status: documented idea.**

### A5 — Quick Search panel chrome
The panel is a plain utility window. Rounded-corner hosting view, softer
shadow, a hair more vibrancy, and row icons (U2) would put it in Spotlight's
league. **Status: documented idea.**

### A6 — Monogram depth
The flat `tint.opacity(0.18)` tile could carry a barely-there vertical gradient
of the same hue; at 26 pt it reads as quality, not decoration.
**Status: documented idea.**

### A7 — Accent color
No explicit accent color is set; the app borrows the system blue. Owning a
VaultSquire accent (used sparingly: open-lock icon, primary buttons) is cheap
brand-building. **Status: documented idea.**

## 6. Delightful / novel ideas

### D1 — Screen-sharing concealment
When the window is being captured (screen sharing, screenshots via
`NSWindow.sharingType = .none` on secret surfaces, or ScreenCaptureKit
detection), mask revealed secrets and TOTP codes. 1Password users recognize
this instantly; almost nobody else does it. Fits this repo's paranoia budget
perfectly. **Status: documented idea.**

### D2 — ⌘⇧C on a Quick Search result copies the password without opening it
Search → arrows → ⌘⇧C → paste, panel never navigates away. The fastest
possible credential path. **Status: documented idea** (pairs with M7).

### D3 — Haptics on lock/unlock
`NSHapticFeedbackManager` `.generic` on successful unlock, `.levelChange` on
lock. Subtle, physical, Mac-native. **Status: documented idea.**

### D4 — "Time to crack" under generated passwords
A playful-but-honest line under the generator: "≈ 3 centuries at 10¹⁰
guesses/s". Teaches entropy better than any meter. **Status: documented idea**
(pairs with M16).

### D5 — Password-age nudge
Using `revisionDate`: a gentle "unchanged for 2 years" caption on the detail
pane. Zero network, occasionally very useful. **Status: documented idea**
(with M10).

### D6 — Next-code preview when TOTP is about to roll
In the last 5 seconds of a window, show the upcoming code dimmed beside the
current one. Saves the "pasted an expired code" dance.
**Status: documented idea.**

### D7 — Lock-screen "knock"
On auto-lock from inactivity, a brief non-modal "Locked — ⌘⇧Space to search
after unlocking" toast teaches the shortcut at exactly the teachable moment.
**Status: documented idea.**

## 7. What is genuinely good (don't regress these)

- **Security architecture**: clipboard ownership via change-count, URI
  confirmation with effective-host display, capability gating enforced in the
  use-case layer (not just disabled buttons), CLI executor with environment
  allowlist, KDF floor/ceiling, fail-closed unknown crypto, generation-checked
  async publication, KDF-change and cross-origin confirmation panels. This is
  better than most shipping password managers.
- **The adversarial-review culture**: `docs/security-review/` with named
  residuals (R5–R8) instead of silent acceptance.
- **Deterministic monogram tiles** with a written-out FNV-1a hash so colors are
  stable across launches and machines.
- **Comment quality**: the comments explain *why*, including the traps that
  were stepped in earlier (toolbar bubble padding, disclosure alignment,
  focus timing on macOS 26). Future maintainers should keep this bar.
- **Test surface**: leakage tests, fuzz tests, cancellation tests, capability
  tests. The UI test identifiers are consistent and comprehensive.
